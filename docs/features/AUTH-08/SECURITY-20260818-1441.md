## Targeted checks (per task brief)

1. **`JWT_SECRET_KEY=CHANGE_ME` placeholder review** — Confirmed genuinely a placeholder, not a functioning secret and not a "hardcoded default password" anti-pattern:
   - `on_startup()` only checks non-empty (`.strip()` truthiness), so `CHANGE_ME` alone would technically pass the check if left unchanged and used to sign a real JWT — but this is the correct scope boundary for AUTH-08 (documented, accepted, and explicitly out of scope per the already-resolved carry-forward item `R-08-jwt-signing-not-yet-implemented`; see below).
   - Both `.env.example`'s comment and `README.md`'s new table explicitly instruct: "Never use the `.env.example` placeholder (`CHANGE_ME`) in production — generate a random value, e.g. `openssl rand -hex 32`." This is adequate operator guidance for a local-dev placeholder, distinguishing it from a silent production fallback.
   - There is no code path that treats `CHANGE_ME` (or any other value) as an implicit default when the env var is *absent* — the fail-fast check requires the var to be explicitly set to *something*. This is the key distinction from a "hardcoded default password" anti-pattern (which would silently substitute a working default). No finding raised; strength-of-value enforcement (e.g. minimum entropy/length check) is a reasonable future enhancement but not a blocking gap for a generic internal admin tool per the active `standard` governance profile.

2. **`docker-compose.yml` literal-secret check** — Confirmed: only `${JWT_SECRET_KEY}` and `${CORS_ORIGINS:-...}` host-shell references appear; no literal secret value anywhere in the file. `CORS_ORIGINS` default fallback (`http://localhost:5173,http://127.0.0.1:5173`) is a non-secret, already-public dev origin list, not a credential.

3. **Fail-fast message / logger.error leakage check** — Confirmed: `logger.error("JWT_SECRET_KEY environment variable is required")` and the paired `RuntimeError` message are both static strings with no interpolation. Neither logs the (absent) value, nor any other secret, nor a stack trace payload beyond Python's own default traceback (which goes to the server process log, not to any client — startup fails before the HTTP server accepts connections).
