   readable `RuntimeError: JWT_SECRET_KEY environment variable is required` as the bare-uvicorn
   case. `docker-compose` itself also warns `"JWT_SECRET_KEY" variable is not set. Defaulting to a
   blank string.` `curl http://127.0.0.1:8000/api/health` → unreachable (HTTP 000). **Matches
   original validation exactly — fail-fast holds with the newer merged backend code layered on
   top.**
2. `docker-compose down` (cleanup), `export JWT_SECRET_KEY=$(openssl rand -hex 32)`,
   `docker-compose up -d backend` → container `crud-backend` reached `Up` status; `docker logs`
   shows `Application startup complete.`; `curl http://127.0.0.1:8000/api/health` → `{"status":"ok"}`,
   HTTP 200. Container torn down cleanly afterward (`docker-compose down`).
