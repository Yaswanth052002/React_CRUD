## Manual OWASP checklist + stack-pattern pass

**Input validation at trust boundaries** — `page` and `page_size` are validated by FastAPI's
`Query(..., ge=1)` / `Query(..., ge=1, le=100)` constraints in `backend/app/api/users.py`,
bounding the page size to a sane maximum (aligned with `.claude/rules/performance-baseline.md`
"pagination on every list endpoint ... max page size"). `search`/`role`/`status` validation is
unchanged from the pre-existing implementation (still plain `Optional[str]`, compared via
ORM `.ilike()`/`==` — no new risk surface introduced by this diff; equality/LIKE comparisons
against enum-backed columns fail closed to "no rows matched" for garbage input, not an
injection vector). Not flagged as a new finding since the diff did not modify that
validation boundary.

**No PII in logs** — no new logging statements were added in this diff; existing logging
posture (none, beyond FastAPI/uvicorn access logs which log request paths, not response
bodies) is unchanged.

**No raw stack traces to users** — `UserService.list_users` raises no new exceptions and adds
no new `except` blocks; existing 404/409 handling in `get_user`/`create_user`/`update_user`
(unchanged by this diff) continues to return `detail` messages only, never stack traces.
`frontend/src/services/userApi.js`'s `normalizeError` (unchanged) continues to strip
Axios/HTTP internals before they reach components.

**Parameterized queries** — confirmed above; `UserRepository._filtered_query`,
`get_all`, and `count_filtered` all route through SQLAlchemy's query builder
(`.filter()`, `.ilike()`, `.limit()`, `.offset()`, `func.count()`) — no raw SQL strings
anywhere in the diff.

**Performance/pagination baseline** — `page_size` is capped at 100 server-side
(`le=100`), and the repository issues one bounded `SELECT ... LIMIT ... OFFSET ...` plus one
`SELECT count(...)` per request — no N+1 pattern, no unbounded fan-out. Matches
`.claude/rules/performance-baseline.md`.

**FastAPI stack pattern (`fastapi-patterns`)** — layering preserved: `api/users.py` still
only parses/delegates, `user_service.py` still holds business logic (offset math, response
assembly), `user_repository.py` remains the only module issuing SQLAlchemy queries. The new
`UserListResponse` is a dedicated Pydantic schema (not the ORM model returned directly),
consistent with "always map through a `schemas/*Read` model."

**React stack pattern (`react-patterns`)** — `Dashboard.jsx` still calls the backend only
through `services/userApi.js` (no direct Axios calls added); the new pagination controls are
plain JSX with `aria-label`/`aria-live` attributes, no new client-side state duplicating
server data beyond `page`/`totalUsers`, which are legitimately new derived-from-server values.

**Authentication/authorization** — this application has no authentication layer at all
(pre-existing, documented as a generic internal admin tool with no regulated domain per
`README.md`/`CLAUDE.md`); this diff does not add, remove, or modify any auth/authz surface,
so it is out of scope for this review and is not flagged as a new finding.
