## Critical findings

### F-001 — Mock login (`userAuthService.login`) is now reachable in the production render tree, granting a universal authentication bypass

- Source: checklist/auth (Authentication and authorization — "every protected endpoint enforces authn AND authz")
- Severity: Critical (escalated from AUTH-01's Medium; the mitigating factor that made it Medium there — "not reachable, zero references from App.jsx/main.jsx, confirmed absent from `frontend/dist`" — no longer holds)
- Carry-forward: `docs/features/AUTH-01/state.json` → `pending_carry_forward[0]`, item `F-004-mock-login-must-be-replaced`, `resolved_at: null` — still open.
- Evidence:
  - `frontend/src/App.jsx` (this diff) mounts `LoginScreen` unconditionally whenever `!isAuthenticated`, i.e. on every fresh browser session with no valid token — this is now the real, reachable entry point AUTH-01's finding anticipated.
  - `frontend/src/components/LoginScreen.jsx` imports `login` from `../services/userAuthService` (unchanged by this diff) and calls it directly — it does **not** call any backend endpoint.
  - `frontend/src/services/userAuthService.js` `login(email, password)` is still the AUTH-01 mock: it resolves a fake token for **any** non-empty `email`/`password` pair and never contacts the backend. Its own header comment says: `// MOCK implementation for AUTH-01 — AUTH-02 owns replacing this with a real backend call.`
  - `frontend/src/services/userApi.js` has zero references to `/api/auth/login` or any auth-related HTTP call — confirmed via grep.
  - AUTH-02's real backend endpoint (`POST /api/auth/login`, `backend/app/api/auth.py` → `AuthService.login`) **does exist** on `feature/AUTH` (implemented, and — separately — its own security review is `BLOCKED`, 1 High / 3 Medium / 8 Low, per `docs/features/AUTH-02/state.json`), but the frontend never calls it.
- Impact: any user who reaches the login screen and types a non-empty string into both fields is authenticated and dropped into the full admin CRUD dashboard (create/update/delete any user record) — a complete, unauthenticated-by-design bypass of the app's only access control, now live in the reachable render path rather than dead code.
- Fix: block merge of AUTH-05 (or gate it behind AUTH-02) until `LoginScreen`/`userAuthService.login` is repointed at the real `POST /api/auth/login` endpoint. This is explicitly the condition AUTH-01's F-004 carry-forward set for "whichever story mounts LoginScreen into App.jsx."
- Override: none present (no `// SECURITY-OK:` comment).
