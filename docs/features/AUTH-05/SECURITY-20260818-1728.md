## F-001 (round 1, Critical) — verified closed

Round 1 finding: `LoginScreen.jsx` called the AUTH-01 mock `userAuthService.login` (resolves for any non-empty email/password, never contacts the backend) — a live universal authentication bypass once mounted into `App.jsx`'s reachable render tree.

Verified by reading current file content directly (not the prompt's claim):

- `frontend/src/services/userApi.js` (current, read in full) now exports:
  ```js
  export async function login(email, password) {
    try {
      const res = await client.post("/api/auth/login", { email, password });
      return res.data;
    } catch (err) {
      throw normalizeError(err);
    }
  }
  ```
  This uses the module's shared `client` (axios instance with `baseURL`/`timeout` already configured) and the same `try { ... } catch (err) { throw normalizeError(err); }` shape as every other exported call in the file (`getUsers`, `getUser`, `createUser`, `updateUser`, `deleteUser`, `getDashboardStats`) — no divergence from the established pattern.
- `frontend/src/components/LoginScreen.jsx` (current, read in full) now imports `{ login, setAuthToken }` from `"../services/userApi"` (was `login` from `"../services/userAuthService"` + `setAuthToken` from `userApi` separately) and calls `await login(email, password)` in `handleSubmit`, exactly as before but now hitting the real endpoint.
- `frontend/src/services/userAuthService.js` — deleted entirely (`git diff e28cf953` confirms `deleted: frontend/src/services/userAuthService.js`, all 21 lines including the mock and its `// MOCK implementation for AUTH-01` header comment removed). No remaining reference to this module anywhere in the diff or a repo-wide grep.
- `backend/app/api/auth.py` → `AuthService.login` (AUTH-02, on `feature/AUTH`) is the real, implemented `POST /api/auth/login` endpoint this now calls.
- Independent evidence already gathered outside this review and spot-checked here: `docs/features/AUTH-05/VALIDATION-20260818-1730.md` records a live `curl -X POST /api/auth/login` with bad credentials returning `401 {"detail":"Invalid email or password."}` — a generic, non-leaking error, consistent with `LoginScreen.jsx`'s `catch { setAuthError(GENERIC_AUTH_ERROR) }` (still present, unchanged).
- AUTH-01's carry-forward `docs/features/AUTH-01/state.json` → `pending_carry_forward[0]` (`F-004-mock-login-must-be-replaced`) now shows `resolved_at: "2026-08-18T17:20:00Z"` with evidence pointing at this exact fix. Confirmed non-`null`.

**F-001 is genuinely closed.** `LoginScreen` no longer reaches any mock; the only path from the login form to an authenticated session is `POST /api/auth/login` against the real backend.

## New-finding check (findings the fix itself could have introduced)

- **Error-normalization pattern**: `login()` follows the identical `try/catch → normalizeError(err)` shape as every other `userApi.js` export — no bespoke error handling, no leaked axios/HTTP internals to the caller. Confirmed by direct read of the full current file (`frontend/src/services/userApi.js`, lines 165–172).
- **No new SSRF surface**: the POST target is a hardcoded literal path (`"/api/auth/login"`) against the module's fixed `client` (`baseURL` from `VITE_API_URL`/localhost default, unchanged) — no user-controlled URL, header, or redirect target is introduced.
- **No new injection surface**: `email`/`password` are passed as a JSON request body via axios (`client.post(url, { email, password })`), not string-concatenated into a URL, query string, or shell/SQL context. Backend-side validation is AUTH-02's concern (already reviewed, PASS).
- **No credential logging**: grepped the full diff (`git diff e28cf953 -U0 -- frontend/src backend/app`) for `console.log`/`print`/`log.*` patterns touching `email|password|token` — zero hits. `LoginScreen.jsx`'s `catch` block sets only the generic `GENERIC_AUTH_ERROR` string in state; no credential or server error text reaches a log sink. Consistent with the deleted mock's own prior comment ("This module never logs credentials") — that invariant now holds in the real implementation too.
- **SAST grep pass** (full pattern table from `security-review-checklist`) against the diff: zero hits (no eval/exec/command injection, no XSS sinks, no JWT `alg:none`, no TLS-verify-disabled, no weak hash/cipher, no hardcoded secrets, no PII-in-logs).
- **Test-file diff** (`LoginForm.test.jsx`, `LoginScreen.test.jsx`): mechanical rename of the mocked module (`userAuthService` → `userApi.login`) and spy target; no new assertions removed, no security-relevant test coverage dropped. TC-02 (call-sequence order: `login` → `setAuthToken` → `onLoginSuccess`) and TC-04/TC-07 (generic error message; password never in DOM/console) still exist and now exercise the real `userApi.login` spy.

No findings introduced by the fix.
