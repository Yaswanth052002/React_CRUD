fields that `Dashboard.jsx` already rendered pre-USR-01 (table rows + `UserDetails` modal) —
this is a straight relocation of existing UI per decision D-01, not a new exposure surface.

plain count with no PII content — matches decision D-03 (client-side derivation, frozen
backend contract, no new field). No PII persisted to `localStorage`/`sessionStorage`/cookies
in the diff.

**Auth / authorization.** No backend files changed; no new protected route, no new
ownership-sensitive mutation path. Pre-existing app-wide absence of authentication is a
known, out-of-scope condition for this generic internal admin tool (README §"Target
platforms": no regulated domain) and is not newly introduced or worsened by this diff — it is
carried forward from prior stories, not a USR-01 finding.

**Errors.** `loadError`/`formError`/toast paths in `Users.jsx` are copied unchanged from the
prior `Dashboard.jsx` implementation — errors still flow through `userApi.js`'s
`normalizeError` and are rendered via `Notification`/inline text, never raw stack traces.

**Crypto.** No crypto-relevant code touched.
